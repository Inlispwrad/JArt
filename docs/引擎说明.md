# 引擎说明（P1 本机版）

2026-10-08。助手实现。标 **推导** 的是实现时的取舍，未经用户确认；规则本身以 [图像生成规则](图像生成规则_gpt-image-2.5.md) 为准。

## 1. 怎么跑

```bash
uv sync
uv run jart presets                  # 官方预设：swap / chain / text
uv run jart presets swap             # 这个预设要填哪些输入
uv run jart plan swap -i 输入.toml    # 预览：每次调用的提示词全文、图片顺序、预估费用、检查结果；不调模型
uv run jart run  swap -i 输入.toml    # 预览，确认后运行；--fake 用假模型演练，不花钱
uv run jart runs / show <运行编号>     # 运行记录 / 一次运行的留底
```

- 输入可以写在 TOML 文件里（示例：`examples/swap.inputs.toml`），也可以 `-s 键=值` 逐个填；同一个键写多次就是多行。
- `--until 节点` 只跑到这个节点；`--pin 生成节点=素材编号` 采用已有结果，这个节点不再调模型（"采用"）。
- 调 OpenAI：本机设 `OPENAI_API_KEY`；云端环境由网络密钥在出口注入，代码不读 key。
- 素材库和运行记录在 `~/.jart`（`JART_HOME` 或 `--home` 可改）。

## 2. 节点

| 节点 | 输入 | 输出 | 主要参数 |
|---|---|---|---|
| 文本 text | — | 文字 | `text` |
| 图像 image | — | 图 | `path` 或 `asset`（素材编号），`revision` |
| 结构 structure | 声明的每张图；文字字段可用连线代替参数 | 请求 | `images`、`objects` `style` `camera` `content` `replace` `action` `size_note` `fixes` |
| 预览 preview | 请求 | 请求（原样） | — |
| 生成 generate | 文字或请求 | 图（第一张） | `model` `size` `quality` `n` `background` `output_format` `pin` |
| 后处理 postprocess | 图 | 图 | `alpha`（默认开：≤8 归 0，≥250 归 255）、`resize`（cover / contain） |
| 输出 output | 图 | — | `name` |

结构节点里每张图要声明 `kind`：`setting` 设定图（要写一句 `role`，如"人设"）、`content_ref` 内容参考图、`action_ref` 动作参考图、`size_frame` 尺寸线框、`edit_target` 要修改的图、`mask` 遮罩。

模板文件就是一个工作流 JSON，加上 `slots`（插槽）声明哪些参数在运行时填。官方预设在 `src/jart/presets/`。

## 3. 结构节点怎样拼提示词

- 不经 LLM，不改写、不增补用户文字。平台自己写的字只有两种：每张图一句角色声明；修图条目的编号。
- 图片顺序 = 声明顺序 = 发给接口的顺序。文字里用 `{{名字}}` 指代图片，拼接时换成"图N"，增删图片后编号不会写错。
- 角色声明：多张图时为"图N是X。"，只有一张图时为实测过的"参考图是X。"。**推导**：设计案写的是"画像N：…"，这里选了与实测说法一致的句式；模板的 `format` 可以改。
- 段落顺序：角色声明 → 物件设定 → 风格 → 镜头 → 内容 → 物件指向替换 → 动作 → 目标尺寸 → 修图条目；段间空一行，不加小标题。**推导**（按"设定输入 → 内容指定"排）。
- 修图（写了 `fixes`）：只发编号的"错在哪＋正确画法"；只有要修改的图一张时不写角色声明。**推导**。

swap 预设拼出来的样子：

```
图1是人设。
图2是匕首设定。
图3是内容参考图。

（画法段原文）

把图3里的刺客换成图1。
把图3里的短刀换成图2。
画面里没有别的主体。

刺客从画面左侧冲向右侧，匕首刺向目标背后。

最终显示在约 130×65 的小图窗、一眼识别。
```

## 4. 检查

| 情况 | 结果 | 依据 |
|---|---|---|
| 有内容参考图，没写物件指向替换或动作描述 | 拦下 | 规则 §3 |
| 没接风格（画法段） | 警告 | 规则 §2、设计案 §6 |
| 有内容 / 动作参考图，又写了镜头词 | 警告 | 规则 §2 写的是动作参考图；内容参考图也算——**推导** |
| 设定图没出现在替换里 | 警告 | 规则 §2"替换说明不完整时原图人物会被保留"——**推导** |
| 参考图或修改对象已被修改两次以上 | 拦下 | 规则 §2 |
| 修图时还写了风格等其他段落 | 警告 | 规则 §2 局部修图 |
| 遮罩：要修改的图没排第一 / 尺寸不同 / 不是带透明的 PNG | 拦下 | API 实测要点 |
| 超过 16 张图、提示词超 32000 字、尺寸不合规（16 的倍数、≤3840、≤3:1、总像素范围） | 拦下 | 官方文档 |
| `{{名字}}` 找不到对应的图 | 拦下 | — |

## 5. 运行与留底

- `plan` 不调模型。`run` 先重算计划，和确认过的不一致就一张都不跑。
- 每次调用留底在 `runs/<编号>/run.json`：接口、提示词全文、图片顺序与 sha256、参数、用量、花费、耗时、输出哈希、错误。原图和输出在 `out/`。
- 素材按 sha256 存，元数据记来源、上游素材和修改次数。
- 修改次数：上传和新生成的图算 0；拿"要修改的图"改一次 +1；后处理不算。**推导**。
- 一个生成节点 `n>1` 时，下游用第一张；要用别的就 `--pin`。
- 模型调用失败：记下错误，该调用不计费，下游跳过。

## 6. 费用

- 价格（官方，2026-10-08 查）：文本输入 $5、图像输入 $8、图像输出 $30（每百万 token）；sunburst / flare 同价。实际花费按接口返回的 usage 算。
- 运行前预估（**推导**）：官方没给 2.5 的输出 token 公式。先用用户实测（2048×1024 high＝1180 token；1086×1448 输入约 2904 token），之后用本机历次真实调用；同质量档没有同尺寸数据时按面积外推；没有该质量档的数据就显示"无法预估"。
