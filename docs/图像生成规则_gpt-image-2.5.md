2026-10-07。**用户定**＝用户原话 / 当场定义；**实测**＝试验结果（样本很小，只作方向）；**推导**＝助手推断，未经用户确认。

## 1. 流程（用户定）

**设定输入 → 内容指定 → 模型输出**

## 2. 设定输入（用户定的五项）

- **提示词语言**（用户最新指定）：原话「提示词全部用中文写」。生图与修图提示词统一中文；关闭任何自动增补。
- **2.5 最高质量档**：Sunburst 支持 `low / medium / high / xhigh / max / auto`，最高为 `quality=max`。依据：https://developers.openai.com/api/docs/models/gpt-image-2.5-sunburst
- **局部修图提示词**（用户纠正）：原话「你就说明错了，然后正确该怎么画，别加多余的提示词导致图像模型理解错误」。只写错误与正确画法，不追加整图保留清单、画风说明或其他冗余限制。
- **参考图修改次数限制**（用户纠正）：原话「你使用的参考图是错的，要避免劣化问题，参考图只能用原始或者经过最多一次修改的」。参考图与编辑目标只能是原始图或从原图修改一次的图；修改两次及以上的结果不能再输入。纠正时回到合规源图，把已确定的修改合并执行，不沿最新修稿逐轮叠改。

| 项 | 用户定的作用边界 | 怎样给 2.5 | 依据 |
|---|---|---|---|
| **风格** | 只能作用到不被确定的风格上；参考设定图本身带风格化 | 文字写画法段。由设定图确定的部分，画风跟着设定图走，文字压不住 | 实测：立绘作人设参考后，画风被拉向立绘的精致动漫；无参考时画法文字只部分落实；删掉画法段会变厚涂 |
| **物件设定** | 文字可以抽象指定；设定图可以明确指定，但风格化随设定图走 | 抽象的用文字；需要精确的用设定图，角色声明一句即可，如"参考图是人设。" | 实测：一句声明与详细保留清单效果相同；用户：多写是多余 |
| **镜头构图** | 只能通过文字定义标准镜头；模型无法理解镜头参考图，只会当成线 | 用标准镜头词汇（越肩视角、受害者第一人称）；不写 VP 坐标，不传构图引导图。若已有动作参考图，透视交给参考图，不再叠加镜头词（实测叠加会加深下半身扭曲） | 用户情报与实测 |
| **内容参考图** | 一模一样的构图，用来替换内容元素（通过物件设定图） | 编辑接口按顺序传图，每张一句角色声明 | 实测：人设、物件还原准确，参考图的构图与画风被带入；替换说明不完整时原图人物会被保留成别的角色 |
| **提示词语言** | 会影响审美 | 同一批素材固定一种 | 实测：同提示中→日，画风转冷、更像日系手游 |

参考图上限：2.5 编辑接口最多 16 张输入图（官方文档）。

## 3. 内容指定（用户定）

- **只用来设计内容**（画什么行为、哪些元素、元素怎样互动），**不描述物件细节**——物件细节归"物件设定"。
- **目标尺寸属于内容的限制**（原话：「目标尺寸，这个应该是内容的限制，参考图也可以传一个只有这个尺寸的线框（如果有参考图槽位富余的话）。」）：内容里写目标尺寸，如"最终显示在约 130×65 的小图窗、一眼识别"；槽位富余时可另传一张尺寸线框图（未实测）。
- **有内容参考图时必须写两样**（原话：「内容提示词缺少了物件指向替换，还有画面内容的动作描述。你重写一下」）：
  1. **物件指向替换**：逐条写清参考图里哪个元素换成哪张设定图，保留哪些，画面里有没有别的主体。
  2. **画面内容的动作描述**：谁、从哪到哪、做什么动作、作用在哪里。

## 4. 模型输出

| 模型 | 结论 |
|---|---|
| **gpt-image-2.5（Images API 直调）** | 当前主力；实测最接近目标画风，内容逻辑较稳 |
| Nano Banana 2.1 / Pro | 不走（用户定）：参考图权重远大于文字；实测偏矢量描边，Pro 不稳定 |
| Codex 自带出图 | 只做探索（写死 gpt-image-2，尺寸 auto） |
| Codex 调 2.5 API | 不用于定稿：会把提示改写成英文标签字段＋脚本增补＋默认 medium |

## 5. 待测

1. 镜头词汇能否稳定落实效果 / 释放 / 中心三种构图。
2. 动作参考图的效果。
3. 参考图数量与细致程度的影响；人设参考与画法段怎样并存。
4. 同一语言下的稳定性。
5. 尺寸线框参考图会不会被画进画面。
