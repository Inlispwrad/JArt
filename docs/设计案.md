# 设计案（草稿 v2）：引导式生图平台

2026-10-07。助手起草，**名称、技术选型、收费细节待用户定**。流程与输入定义沿用 docs/图像生成规则_gpt-image-2.5.md。项目名 JArt（用户定）。

## 0. 用户原话

> 有点想做成一个单独的服务来用，使用一个软件来调，既可以走 mcp 也可以走编辑界面。你先帮我起草一下设计案。这个可能要做成独立项目。
>
> 不考虑深度商业化，我没有营销的想法，就做成一个 side project。有人利用可以小额度盈利的，我就吃一个平台和功能调用的钱。其实更多是我自己用。
>
> 不是真有人要用，是实际就是有人要用。只是我不大规模营销，保证最基本功能需求，然后我就接 api 卖我做出来的功能调用。
> 我打算做成引导式生图。
> 开一个节点，可以输入提示词，也可以直接把它从提示词调一次模型变图片，变为输入参数给下一个节点。
> 我预设一些偏向结构和解决方案，然后让用户自己做一套属于自己的开发模板。用户可以保存这些模板反复使用。就真的只赚平台和功能调用。

## 1. 定位

- 已有实际用户，小规模、不做营销；保证最基本的功能需求。
- 收入只来自平台费和功能调用费。
- 用户自己也是用户之一，用同一个平台，不另做本地版。
- 入口两个：网页编辑界面（节点画布）、开放 API ＋ 远程 MCP，用户的 Agent 可以直接调。

## 2. 核心交互：引导式节点

| 节点 | 作用 |
|---|---|
| **文本** | 写提示词或一段设定文字 |
| **图像** | 上传或从素材库选一张图 |
| **生成** | 输入文本，可选接入若干图像；调一次模型，输出图像。输出可以接到下游节点，当作参考图（人设、物件、构图参考…）使用 |
| **结构**（预设，即"引导"） | 按工作流规则组织输入：风格、物件设定、镜头构图、内容参考图、目标尺寸、语言、替换表、动作。自动生成"画像N：…"角色说明，缺项时提示或拦下 |
| **预览** | 显示最终发给模型的提示词全文和图片顺序，确认后才扣费运行 |
| **后处理** | 透明清理（主体 253/254 → 255，淡雾 → 0）、裁切适配尺寸 |
| **输出** | 结果、并排对比、采用 / 否决、下载 |

一条典型的链：

```
[文本：角色描述] → [生成：人设图] ─┐
[图像：匕首设定] ──────────────────┤
[图像：构图参考] ──────────────────┼→ [结构：替换表＋动作＋风格＋语言] → [预览] → [生成：技能图] → [后处理] → [输出]
[文本：画法段] ────────────────────┘
```

## 3. 模板

- **官方预设**：由用户提供的结构和解决方案，例如：
  - "人设＋物件＋构图参考替换"（特调暗杀）
  - "无参考纯文字＋画法段"
  - "成套图标"
- **用户模板**：用户在预设基础上改出自己的节点图并保存，暴露几个插槽（换人设、换动作文字），反复使用。
- 模板只存结构和文字。图像素材按用户隔离存放。

## 4. 收费与额度（建议，待定）

- 每次调用费用＝模型成本＋平台费，运行前显示预估费用。
- 预付额度，余额不足不运行，避免欠费。
- 失败的调用不扣平台费（模型方已扣的成本另议）。
- 平台持有模型 key，用户看不到；是否允许用户自带 key，待定。

## 5. 平台必须承担的事

| 事项 | 做法 |
|---|---|
| 账号与隔离 | 每个用户独立的素材、模板、运行记录 |
| 计量 | 每次运行记录模型用量、费用、耗时 |
| 防滥用与费用风控 | 预付额度、单次 / 单日上限、限流、出图排队 |
| 内容审核 | 调用模型方的审核接口，加上平台自己的规则。用平台的 key 替用户出图，平台要对内容负责，须遵守模型方的使用政策 |
| 地区与条款 | 模型方的服务地区限制会约束能接哪些用户；需要服务条款、隐私政策 |
| 数据 | 素材与结果的保存期限、删除功能 |

## 6. 把规则做进平台

本节只写平台怎样实现已定规则；规则本身以 docs/图像生成规则_gpt-image-2.5.md 为准，本设计案不新增、不修改规则。

| 规则 | 体现方式 |
|---|---|
| 参考图角色写一句就够 | 结构节点自动生成"画像N：…" |
| 有内容参考图时，必须写替换和动作 | 缺项不让运行 |
| 风格（画法段）不能省 | 未接风格时警告 |
| 目标尺寸属于内容限制 | 尺寸进内容段 |
| 提示词语言影响画风 | 语言是模板级设定 |
| 不偷偷改写提示 | 拼接按固定规则，不经 LLM；翻译若做，作为单独节点，译文显示并确认 |
| 直调 Images API | 模型适配器记录实际请求原文 |
| 透明输出要清理 | 后处理默认开启，原图另存 |
| 记录别带偏 Agent | 运行日志默认不通过 MCP 暴露，只暴露模板和用户确认的结论 |

## 7. 架构（建议）

```
网页（节点画布） ─┐
开放 API ─────────┼─→ API 服务 ─→ 任务队列 ─→ 执行器（调模型、后处理）
远程 MCP ─────────┘        │
                           ├─ 数据库：用户、模板、运行、额度
                           ├─ 对象存储：素材与结果
                           └─ 支付、审核
```

- 后端：Python ＋ FastAPI，执行器复用实验脚本逻辑（见 docs/API实测要点.md）；数据库 Postgres；S3 兼容的对象存储。
- 前端：React ＋ React Flow（节点画布）。
- 部署：一台小规格云主机或容器起步。

## 8. 分期

| 期 | 内容 | 完成标准 |
|---|---|---|
| P1 引擎 | 节点执行（文本 / 图像 / 生成 / 结构 / 预览 / 后处理）、链式生成、gpt-image-2.5 适配、计量 | 用模板复现特调暗杀（测试素材需用户提供），并支持"先生成人设图，再接到下游"的链 |
| P2 平台 MVP | 账号、预付额度、节点画布、模板保存、任务队列、内容审核 | 用户和一位实际用户能独立搭模板出图并扣费 |
| P3 开放接口 | 开放 API、远程 MCP（用户令牌）、支付上线 | 用户的 Agent 能用自己的令牌调模板 |
| P4 扩展 | 更多模型后端、批量运行、模板分享 | 按实际需求 |
